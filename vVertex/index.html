02. Access_Matrix

系統採用高度模組化的 Firestore Security Rules，配合 React 元件層級的渲染控制。不同角色擁有嚴謹的資訊隔離邊界。

Role (角色) Core Feature Pro (業務優勢)
Admin 動態權限設定 即時生效 (Hot-reload) 權限節點，毋須重啟系統即可動態建立自訂安全角色。
Coordinator 自動化課程排期 全自動排程演算法 (Automated Scheduling Algorithm)，秒速運算並主動攔截導師或課室撞期。
Finance 付款核實與對賬 財務數據屏障 (Data Shielding)，專注加密入賬核對，確保資金流向絕對精準。
Staff 全局只讀監察 全局唯讀防護網 (Read-only Sandbox)，安全讀取底層數據以解答客戶查詢，做到零誤刪風險。
Instructor MTM 報表匯出 一鍵觸發 MTM 協議 (One-click Protocol)，極速匯出符合微軟官方標準嘅學生名冊。

03. Mobile_Terminal

1

儀表板載入 (Dashboard Fetch)

登入後，系統會透過用戶 UID 篩選 registrations 集合，渲染「即將到來」及「歷史」課表。

2

觸發掃描 (ML Kit Scan)

點擊懸浮按鈕喚醒相機，掃描導師畫面上的 QR Code 獲取 Token (例如 DYN-LESSONID_AM-RANDOM)。

3

解析令牌 (Token Decryption)

驗證 Token 有效期 (60秒動態過期時間)，拆解出對應的 Lesson ID 及上下午 (AM/PM) 時段標記。

4

直寫資料庫 (Direct Check-in)

繞過傳統 API，利用 Firestore 規則直接向 attendance/{lessonId}_{userId} 寫入報到記錄。

Security Rules // 隔離協議 FAQ

Q: 為何 App 內不檢查 `role == 'student'`？

A: 基於資料隔離架構。App 首頁直接查詢包含目前用戶 UID 的 `registrations`。因為導師及 Admin 不會「報名」課程，其課表自然為空，無需額外執行前端 Role Check。

Q: 導師若掃描 QR Code 會發生什麼事？

A: 寫入路徑為 `attendance/{lessonId}_{userId}`。導師掃描只會以自己的 UID 產生一筆幽靈記錄，完全不會干擾真實學生的點名名冊，符合最小權限 (Least Privilege) 寫入原則。
